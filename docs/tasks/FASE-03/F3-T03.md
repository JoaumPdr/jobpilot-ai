# F3-T03 — Sanitização e defesa de entrada

- A tarefa usa `feat/f3-t03-sanitizacao-entrada-llm` a partir de `phase/03-camada-llm`.
- Depende de [F3-T02](F3-T02.md).
- Prepara uma entrada delimitada para a análise, com tamanho previsível e apenas os dados de perfil pertinentes à vaga.
- Segue o [backlog](../../BACKLOG.md#fase-3--camada-llm--branch-phase03-camada-llm--tag-fase-03) e a [política de privacidade](../../privacy-and-sources.md).

## Escopo

- Descrição sanitizada dentro de um campo JSON na mensagem do usuário. O prompt de sistema permanece em uma mensagem própria.
- Limite de 8.000 caracteres na descrição e sinal de truncamento. As habilidades do perfil vêm do matching, em nomes do catálogo local, com ausências explícitas em uma lista própria.
- Prompt `job-analysis-v2` com instruções para interpretar os campos delimitados. A chamada do serviço, a comprovação das evidências e o cache ficam nas tarefas correspondentes.

## Como verificar

1. Testar descrições sintéticas com aspas, quebras de linha, caracteres de controle e texto apresentado como instrução. Conferir que a mensagem de sistema e o perfil permanecem iguais.
2. Cobrir o limite, campos opcionais e seleção de habilidades pertinentes. Conferir que nomes livres e trechos do perfil ficam fora do payload.
3. Exercitar o fluxo com o provedor falso, validar a versão do prompt e rodar a suíte completa, Ruff e cobertura.

A alteração no formato de entrada exige a nova versão do prompt e a atualização do teste do contrato. A tarefa mantém essas mudanças juntas com a documentação correspondente.
