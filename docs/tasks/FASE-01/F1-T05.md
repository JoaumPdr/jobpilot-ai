# F1-T05 — Cadastro manual de vaga

- **Fase / Branch:** Fase 1 — Núcleo sem IA · `phase/01-nucleo-sem-ia`
- **Branch da tarefa:** `feat/f1-t05-cadastro-manual` (criada a partir da fase)
- **Depende de:** F1-T04 (normalização, canonização de URL e fingerprint)
- **Objetivo (1–2 frases):** permitir cadastrar uma vaga manualmente pela API, gravando texto normalizado para exibição, `canonical_url` e `fingerprint`, e sinalizando duplicatas em vez de gravar lixo silenciosamente.
- **Critérios de aceitação canônicos:** `docs/BACKLOG.md` → F1-T05. Esta ficha **não** cria critérios próprios.

---

## Decisões de desenho

| Tema | Decisão | Por quê |
|------|---------|---------|
| Endpoint | `POST /jobs` (sem `GET`/listagem nesta tarefa) | listagem e filtros são F1-T08; o escopo aqui é só o cadastro |
| Duplicata **certa/quase certa** | camada 1 (`source` + `external_id`) e camada 2 (`canonical_url`) → `409 conflict` com `details` contendo `job_id`, `layer` e motivo | essas camadas identificam a mesma vaga; gravar duplicaria o catálogo sem necessidade |
| Duplicata **provável** | camada 3 (`fingerprint`) → `201 created` com `duplicates[]` no corpo e `layer: "fingerprint"` | o fingerprint pode coincidir entre vagas realmente distintas; o usuário decide depois (F1-T07) |
| Confirmação/merge | **não** preenche `duplicate_of_job_id` nesta tarefa | a confirmação humana com `duplicate_of_job_id`, listagem e desfazer são da F1-T07 |
| Texto | `title`, `company` e `location` exibidos com espaços colapsados, acentos e caixa preservados | normalizar para comparação sem alterar o que o usuário vê (regra do `PLANO.md` §6.2) |
| Modalidade/senioridade | strings livres na entrada, convertidas por `normalize_work_mode`/`normalize_seniority`; desconhecido vira `desconhecido` | aceita "home office", "Sênior", etc., sem inventar valor |
| URL | validada com `canonicalize_url` no schema (422 se inválida) e recanonizada no serviço | URL inválida é erro de payload, não 500; a forma canônica é a base da dedup |
| `source` | default `"manual"`, sobrescrevível | o cadastro manual é uma origem rastreável como qualquer outra |
| Concorrência | `IntegrityError` no commit (índice único `(source, external_id)`) → rollback + 409 | duas requisições simultâneas não podem gerar 500 |
| Race na camada 2 | sem índice único em `canonical_url` (modelo da F1-T03), a checagem é "melhor esforço" | criar índice único impediria vagas legitimamente repetidas em portais diferentes; a F1-T07 revisa |

## Contrato

```json
POST /jobs
{
  "title": "Engenheira de Dados",
  "company": "Empresa X",
  "url": "https://empresa.com/vagas/123?utm_source=linkedin",
  "location": "São Paulo",
  "work_mode": "home office",
  "seniority": "Sênior",
  "description": "Texto livre.",
  "source": "manual",
  "external_id": null,
  "salary_min": "12000.00",
  "salary_max": "18000.00",
  "currency": "brl",
  "posted_at": "2026-11-10T12:00:00Z"
}
```

Resposta `201`:

```json
{
  "job": { "...": "vaga persistida, com canonical_url e fingerprint" },
  "duplicates": [
    {
      "job_id": "3f1c2a9e-6b7d-4c8a-9e10-2a4b6c8d0e12",
      "title": "Engenheira de Dados",
      "company": "Empresa X",
      "source": "manual",
      "canonical_url": "https://empresa.com/vagas/123",
      "layer": "fingerprint"
    }
  ]
}
```

## Plano de testes

- **Serviço (unitário):** normalização de exibição, enums, URL canônica, fingerprint,
  `source` default, camadas 1/2 → 409, camada 3 → criação + aviso, localização
  diferente → sem aviso, falha de integridade → rollback + 409.
- **API:** 201 com corpo e `duplicates: []`; 409 nas camadas 1 e 2 com `details`;
  201 + aviso na camada 3; 422 para URL inválida, faixa de salário invertida,
  moeda fora do ISO e campo desconhecido; `X-Request-ID` no erro.

## Riscos

- **Tamanho acima do alerta (~450 linhas de código/teste, 8 arquivos):** a
  tarefa foi mantida inteira porque schema, serviço, repositório e rota formam
  uma unidade coesa (o contrato só existe completo); dividir deixaria a API sem
  uma rota funcional em qualquer metade.
- O fingerprint ignora descrição e salário: vagas realmente distintas com mesmo
  trio empresa/título/local aparecem como "provável" (aviso, não bloqueio).
- A camada 2 não tem garantia de unicidade no banco; concorrência extrema pode
  criar duas linhas com a mesma `canonical_url`. A F1-T07 revisa esse caso.
- `posted_at` sem fuso é interpretado como UTC para não gravar horário local
  ambíguo no `TIMESTAMPTZ`.
