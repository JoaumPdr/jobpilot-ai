## Endpoints da F1-T02-a

| Método | Rota | Sucesso | Erros |
|--------|------|---------|-------|
| `POST` | `/candidates` | 201 + perfil | 409 e-mail duplicado, 422 validação |
| `GET` | `/candidates/{candidate_id}` | 200 + perfil (com preferências, se houver) | 404 |
| `PATCH` | `/candidates/{candidate_id}` | 200 + perfil | 404, 409, 422 |
| `DELETE` | `/candidates/{candidate_id}` | 204 | 404 |
| `GET` | `/candidates/{candidate_id}/preferences` | 200 | 404 (candidato ou preferências inexistentes) |
| `PUT` | `/candidates/{candidate_id}/preferences` | 200 (upsert idempotente) | 404, 422 |

- `PATCH` usa campos opcionais com `exclude_unset=True`; `null` explícito em campo obrigatório (`name`, `resume_text`) → 422.
- `PUT /preferences` substitui o conjunto inteiro (idempotente) e cria a linha 1:1 se não existir.
- `GET /candidates/{id}` inclui `preferences` (objeto ou `null`); skills/experiências entram na `-b`.

## Estrutura dos JSONB (confirmada)

- `education`: lista de objetos com `institution` e `degree` obrigatórios; `field_of_study`, `start_date`, `end_date`, `description` opcionais. Datas em ISO (`YYYY-MM-DD`); `end_date >= start_date` quando ambas informadas. `extra="forbid"`.
- `languages`: lista de `{name, level}`, com `level` em `básico`, `intermediário`, `avançado`, `fluente`, `nativo` (valores acentuados, como no CHECK de `candidate_skills.level`). `extra="forbid"`.
- `knockout_rules`: objeto JSON (`dict[str, Any]`), sem chaves fechadas nesta fase — as regras serão formalizadas na F2-T03; o banco só garante JSON válido.
- `education`/`languages` são persistidos com `model_dump(mode="json")` para virar JSON serializável.

## Formato de erro padronizado

```json
{
  "error": "not_found",
  "message": "Candidato não encontrado.",
  "request_id": "…",
  "details": [{"field": "email", "message": "..."}]
}
```

- `details` só aparece em 422 (`RequestValidationError`) e é omitido nos demais.
- `request_id` vem do `contextvars` do structlog (middleware existente); fallback `"unknown"`.
- 409 (`conflict`) para e-mail já cadastrado; 404 (`not_found`); 422 (`validation_error`).

- `years` e `skills` não entram nesta sub-tarefa; o `CandidateRead` será estendido na `-b` (mudança aditiva).
- E-mail único é garantido por índice funcional; a corrida entre dois `POST` simultâneos é traduzida de `IntegrityError` para 409.
- Dependência nova (`email-validator`) exige `uv add` + `uv.lock` atualizado, senão o CI falha com `uv sync --locked`.
