# F1-T03 — Modelos e migração de vagas

- **Fase / Branch:** Fase 1 — Núcleo sem IA · `phase/01-nucleo-sem-ia`
- **Branch da tarefa:** `feat/f1-t03-vagas` (criada a partir da fase)
- **Depende de:** F0-GATE (migrações e fixtures de banco)
- **Objetivo (1–2 frases):** criar as tabelas `jobs` e `import_batches` com os enums de modalidade/senioridade, as constraints de deduplicação e os índices de busca, em uma migração reversível. As funções de normalização entram na F1-T04.
- **Critérios de aceitação canônicos:** `docs/BACKLOG.md` → F1-T03. Esta ficha **não** cria critérios próprios.

## Decisões de desenho

| Tema | Decisão | Por quê |
|------|---------|---------|
| Enums | `VARCHAR` + `CHECK`, com `StrEnum` em Python (`WorkMode`, `Seniority`, `ImportKind`) | mesmo padrão de `candidate_skills.level`; evoluir valores não exige `ALTER TYPE` |
| `work_mode` | `remoto`, `híbrido`, `presencial`, `desconhecido`; **NOT NULL**, default `desconhecido` | o plano sempre tem um valor; `NULL` não acrescentaria informação |
| `seniority` | `estágio`, `júnior`, `pleno`, `sênior`, `especialista`, `desconhecido`; **NOT NULL**, default `desconhecido` | o plano lista "…"; `especialista` cobre o caso comum sem inventar taxonomia na F1-T04 |
| `import_batches.kind` | `csv`, `manual`, `api` | origem do lote, conforme `PLANO.md` §5.1 |
| `jobs.url`/`canonical_url`/`fingerprint` | **NOT NULL** | a vaga só entra depois da normalização (F1-T04/T05); dedup depende dos três |
| `jobs.import_batch_id` | FK opcional, `ON DELETE SET NULL` | vaga manual não tem lote; apagar o lote não apaga vagas |
| `jobs.duplicate_of_job_id` | FK opcional para `jobs`, `ON DELETE SET NULL`, CHECK `<> id` | só o usuário confirma duplicata (F1-T07); nada é apagado automaticamente |
| Unicidade de ID externo | índice único **parcial** `(source, external_id) WHERE external_id IS NOT NULL` | CSV/manual sem ID externo não colidem entre si |
| Busca/dedup | índices em `fingerprint` e `canonical_url` (não únicos) | camadas 2 e 3 da dedup; duplicata provável **sinaliza**, não bloqueia |
| Salário | `numeric(12,2)` + moeda ISO de 3 letras; CHECKs `>= 0` e `max >= min` | mesma precisão do perfil; sem conversão de moeda nesta fase |

## Plano de testes

- único parcial `(source, external_id)`: bloqueia repetido com ID, permite vários `NULL` e mesmo ID em fontes diferentes;
- CHECKs de `work_mode`, `seniority`, `kind`, salários negativos/fora de faixa e auto-duplicata;
- counters negativos de `import_batches` e `finished_at < started_at`;
- FKs: lote inexistente → erro; apagar lote → `import_batch_id` vira `NULL`;
- apagar vaga referenciada como duplicata → `duplicate_of_job_id` vira `NULL`;
- índices `ix_jobs_fingerprint` e `ix_jobs_canonical_url` presentes em `pg_indexes`.

## Riscos

- Valores acentuados no CHECK exigem cuidado com a codificação do arquivo de migração (UTF-8).
- `fingerprint` NOT NULL desloca a responsabilidade de cálculo para a F1-T04/T05 — nenhuma rota grava vaga antes disso.
- `especialista` é uma extensão explícita do "…" do plano; se a F1-T04 preferir outra taxonomia, basta ajustar o CHECK na migração da própria tarefa.
